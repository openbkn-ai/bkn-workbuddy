# 项目进度

> 更新：2026-10-22。这是公开仓库的简版进度；验收原始记录、交接文档和宿主探针放在内部仓库，文中以“内部记录”指代。

## 目标

让 WorkBuddy 用户在对话中安全地查询企业授权的 OpenBKN 业务知识网络，每一轮问答都在 OpenBKN 平台留下可审计的业务溯源（在 OpenBKN Studio 中查看）。

## 当前状态

| 模块 | 状态 |
| --- | --- |
| `packages/core` | 纯逻辑：工具契约与指纹、知识网络目录与选择、任务绑定、轮次状态机、生命周期结果、溯源投影、场景包与评测包校验。单元测试通过 |
| `packages/bridge` | 本地 MCP 桥接器：任务与网络一次性绑定（选网络需用户确认）、只读白名单透传、契约指纹门槛、按轮开记录和收尾、Studio 溯源链接（企业版）、失败时禁止沿用旧数据。单元测试通过；与测试平台的实时端到端检查 20/20（业务对象引用一项因平台原因未产出） |
| `gateway` | 签名凭证网关（Go，零依赖）：凭证只在系统凭据库（macOS 钥匙串 / Windows DPAPI）；固定来源、拒绝重定向、可选私有 CA、响应大小上限；只读平台能力查询。测试通过 |

当前主干上的桥接器仍支持两种记录方式：用户级 Hook（默认）和由模型开记录、收尾。

## 已定方向（2026-10-21）

- **不再使用 Hook**，统一由模型开记录和收尾，与 bkn-dsh 一致，目标是能从 WorkBuddy 连接器市场直接安装。方案见 [`docs/plans/2026-10-20-marketplace-connector.md`](plans/2026-10-20-marketplace-connector.md)。
- 业务溯源统一在 OpenBKN Studio 查看，插件不再自己展示依据（TECHNICAL_PLAN §0.12）。

## 验证要点（来自内部记录）

- WorkBuddy 连接器包不能带 Hook；在“市场 API 模式”下，非官方连接器无法在本地预先验证，必须走开放平台上架或测试通道。
- 通用插件市场的本地目录安装方式可用（macOS 实测）；MCP 由 WorkBuddy 托管的 Node 启动，系统凭据库和私有 CA 访问正常。
- 模拟数据测试中，模型在 9/9 个业务轮里主动开记录并在回答前收尾；用户中途停止的轮次不会收尾，由下一次查询补记为失败。
- Windows 沙箱下，MCP 进程看不到 `%LOCALAPPDATA%` 下事先存在的文件；数据目录改为 `~/.bkn-workbuddy`。

## 下一步
